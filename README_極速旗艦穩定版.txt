【旗艦功能】
1. iPhone / Android 共用 PWA。
2. 12 個高鐵車站完整選單。
3. 單程 / 去回程。
4. 快速起訖站預設。
5. 去程 / 回程日期時間。
6. 車廂偏好。
7. 全票、孩童票、敬老票、愛心票、大學生票人數。
8. 基本張數檢查：單程最多 10 張；去回程每方向最多 5 張。
9. 多行程管理。
10. 目前「主攻行程」。
11. 開賣時間秒級倒數。
12. 開賣前 30 / 10 / 5 / 1 分鐘提醒。
13. 系統通知（瀏覽器支援時）。
14. Android 震動提醒。
15. 提示音。
16. Screen Wake Lock 保持螢幕喚醒。
17. 一鍵複製行程摘要＋直達高鐵官方網路訂票。
18. 主攻行程單欄快速複製。
19. 一鍵產生「開賣提醒」.ics 行事曆。
20. 一鍵產生「乘車行程」.ics 行事曆。
21. 狀態：計畫中 / 待開賣 / 待訂票 / 已訂位 / 已付款 / 已取票 / 已取消。
22. 訂位代號紀錄。
23. 付款期限紀錄。
24. 依開賣時間排序。
25. 依乘車日期排序。
26. JSON 完整備份與還原。
27. 離線開啟 PWA 介面。
28. 官方訂票、時刻票價、開放時程、規定快捷入口。
29. 不保存身分證、護照、信用卡等高敏感交易資料。

【一般 29 日規則參考】
PWA 內「一般29日：選擇＋28日乘車日」按鈕會以使用當天為基準，自動計算「今天＋28天」，直接帶入去程日期；在支援 showPicker 的手機瀏覽器會接著跳出日期選擇器，讓使用者直接確認或改選。
此功能是一般29日預售邏輯的快捷選日，不代表特殊疏運或週五／週六延伸訂位的實際開放日期。
週五／週六延伸訂位、疏運或特殊公告可能不同，務必以高鐵官方公告為準。

【GitHub Pages 安裝】
1. 建立 GitHub repository，例如 thsr-quick-booking。
2. 解壓縮本 ZIP。
3. 將所有檔案上傳至 repository 根目錄。
4. GitHub → Settings → Pages。
5. Branch 選 main，Folder 選 /(root)。
6. Save。
7. 等 GitHub Pages 網址產生後，用手機開啟。

Android：Chrome → ⋮ → 安裝應用程式／加到主畫面。
iPhone：Safari → 分享 → 加入主畫面。

【穩定版設計原則】
高鐵官方訂票系統位於 irs.thsrc.com.tw，與 GitHub Pages PWA 不同網域。
本版不使用容易因官網 DOM 改版而失效的自動填表／自動送出，也不嘗試破解驗證或自動付款。

極速流程：
行程預存 → 開賣倒數 → 一鍵複製摘要 → 開官方訂票 → 在官方系統完成車次選擇與交易。

【資料安全】
資料只存在目前裝置 localStorage。
不要在公用手機保存訂位代號。
本 PWA 刻意不提供身分證號、護照號碼、信用卡號、安全碼儲存欄位。


【v1.2 身分證安全模式＋官網一鍵填表】

身分證保存方式可自行選擇：
1. 不保存
   - 不寫入 localStorage / sessionStorage。
   - 只在目前畫面記憶體中使用。

2. 本次暫存
   - 使用 sessionStorage。
   - 適合本次訂票期間使用。
   - 一般在本次瀏覽工作階段結束後清除。

3. 加密保存
   - 使用 Web Crypto。
   - PBKDF2-SHA-256（180,000 次）衍生金鑰。
   - AES-GCM 256-bit 加密後才寫入 localStorage。
   - 必須輸入自訂解鎖碼才能還原。
   - 完整身分證不會被匯出到 PWA JSON 備份。

官網填表方式可另外選擇：
A. 不自動帶入身分證
B. 執行填表時再詢問（建議）
C. 自動預填

注意：
若選擇 C「自動預填」，為了讓跨網域的 Safari / Chrome JavaScript 書籤可以填入身分證，
該次產生的 bookmarklet 會含有身分證明文。
因此 PWA 在複製前會再次警告。
若重視隱私，建議使用 B「執行填表時再詢問」。

【一鍵填表】
PWA 會依目前主攻行程產生 JavaScript 書籤程式，嘗試帶入：
- 出發站
- 到達站
- 單程 / 去回程
- 去程日期與時間
- 回程日期與時間
- 各票種人數
- 身分證（依使用者選擇）

高鐵官網若修改 DOM / 欄位結構，部分欄位可能需要更新。
本功能不自動付款、不破解驗證、不自動按最終送出。


============================================================
【v2.0｜半自動完成訂位旗艦版】
============================================================

v2.0 自動化範圍：
自動填表 → 自動查詢 → 依規則選車 → 最後確認前停止。

不會自動：
- 破解 / 辨識驗證碼
- 繞過簡訊或身分驗證
- 自動按最終確認送出
- 自動付款
- 儲存信用卡號 / 安全碼

【訂位助手模式】
1. 只自動填表
2. 填表＋自動按查詢
3. 填表＋查詢＋自動選車（最後確認前停止）

【選車規則】
A. 指定時間後第一班
B. 最接近指定時間
C. 指定車次優先

指定車次可設定：
- 指定車次 1
- 備選車次 2
- 備選車次 3

若找不到符合條件的車次，助手會停止讓使用者手動選擇，不會亂點。

【時間容許範圍】
可設定 0～180 分鐘。
例如希望 08:00 出發、最接近指定時間、容許 60 分鐘，
助手只會在可辨識的 07:00～09:00 車次中挑最接近 08:00 的結果。

【換頁後如何繼續】
助手在高鐵官網 sessionStorage 寫入本次設定。
若官網換頁導致腳本中止，可在下一頁再次執行同一個「高鐵訂位助手」書籤。

【官網診斷工具】
若官網改版造成某些欄位無法自動辨識：
1. PWA 按「複製官網診斷工具」。
2. 把它設成書籤。
3. 在出問題的高鐵官網頁面執行。
4. 工具只收集欄位/按鈕的結構名稱與文字，不收集 input value。
5. 把診斷結果貼回 ChatGPT，可再製作精準 selector 更新版。

【安全原則】
v2.0 採「辨識不到就停止」。
不會因為找不到正確按鈕就隨便點擊。
驗證、最終確認與付款必須由本人操作。
